# Боты мини-игр Dota 2 — Dark Carnival

Два бота, которые играют в мини-игры ивента **Dark Carnival** вместо вас:
смотрят в экран, распознают происходящее и жмут клавиши.

| Бот | Мини-игра | Что делает | Результат |
|---|---|---|---|
| **Печаталка** | «Атака автоматонов» | читает слово над врагом и печатает его | 212 слов за партию, ~3 слова/с |
| **Арканоид** | «Сапожный снос» | ведёт тележку под мяч, проходит уровни | **3725 очков, уровень 4** |

Рекорд арканоида — 3725 при личном рекорде владельца аккаунта 1640. Бот сам
нажимает «Играть», сам перезапускается после проигрыша и играет бесконечно.

## Как запустить

Нужен Windows, Python 3.9+ и Dota 2 в **оконном** режиме (не эксклюзивный
полноэкранный — иначе снимок экрана будет чёрным).

```bash
pip install -r requirements.txt
python run.py            # меню
python run.py doctor     # проверка: питон, библиотеки, tesseract, окно игры
```

Или двойным кликом по нужному файлу:

| Файл | Что делает |
|---|---|
| `Меню.bat` | меню выбора |
| `Арканоид — играть.bat` | боевой режим арканоида |
| `Арканоид — вхолостую.bat` | всё видит и считает, но **не нажимает** клавиш |
| `Печаталка — играть.bat` | боевой режим печаталки |
| `Печаталка — вхолостую.bat` | сухой прогон |
| `Проверить окружение.bat` | диагностика |
| `Тесты.bat` | 209 тестов |

**Горячие клавиши: F10 — старт/стоп, F12 — выход.** Работают глобально, жать
можно прямо из игры. Первый запуск делайте вхолостую (`--dry`) — увидите, что
бот распознаёт, ничего при этом не нажимая.

Для чтения счёта и слов нужен [Tesseract OCR](https://github.com/UB-Mannheim/tesseract/wiki).
Ищется сам: рядом с проектом (`Tesseract-OCR\tesseract.exe`), в `Program Files`,
в `%LOCALAPPDATA%`, либо путь можно задать переменной `TESSERACT_EXE`.

## Про баны — читать обязательно

Боты **не трогают память игры, не инжектят DLL и не подключаются к сети Valve**.
Они делают ровно то же, что человек: снимают картинку с экрана и отправляют
нажатия клавиш через штатный `SendInput`. С точки зрения античита это
обычный ввод.

Тем не менее: **вы используете это на свой страх и риск.** Если аккаунт
получит ограничение — это не ответственность авторов проекта. По опыту
использования банов не было и не ожидается: мини-игры Dark Carnival — это
развлечение внутри клиента, а не рейтинговый матч, и никакого преимущества
над другими игроками бот не даёт, кроме места в таблице рекордов мини-игры.
Не используйте это в матчах — бот к ним и не приспособлен.

## Как это работает

### Печаталка («Атака автоматонов»)

Над каждым врагом висит слово; у текущей цели ниже идёт строка прогресса, где
**серые** буквы уже набраны, **жёлтая** — следующая, **белые** — остаток.
Бот берёт жёлтую и белые: это ровно то, что осталось напечатать, поэтому
набранное не вводится повторно.

Дальше маска букв уходит в Tesseract (whitelist A-Z), а результат чинится по
словарю героев и предметов Dota — но **якорно**: слово целиком правится по
словарю (`LEUS` → `ZEUS`), а остаток подгоняется только к суффиксам текущего
слова. Искать остаток по всему словарю нельзя — на живом прогоне `MAELSTR`
превращался в `MASTER`, а `ITE` (хвост FROSTBITE) в `IT`.

Неожиданная находка: враги несут не только имена, но и **целые реплики** —
«HAHA I COULD EAT A WALRUS», «AXE LIKES THIS VERY MUCH». Они длинные, а очки
растут с длиной текста, так что это самые ценные цели. Словарь для них не
нужен: печатаются как есть.

### Арканоид («Сапожный снос»)

Мяч ищется **разницей соседних кадров** — двигается только он. По двум
последним позициям считается скорость и предсказывается точка пересечения
линии платформы **с учётом отскоков от стен** (зеркальная развёртка — одна
формула вместо пошагового моделирования). Просто ехать за мячом нельзя:
тележка идёт ~200 px/с, мяч быстрее и пересекает поле раньше.

Когда есть запас времени, мяч принимается **краем** платформы, чтобы послать
его в сторону оставшихся блоков; когда времени в обрез — центром, потому что
краем промахнуться проще.

## Что было неочевидно (и стоило отладки)

Эти вещи не гуглятся — каждая найдена замером на живой игре.

**Мини-игра не получает клавиши, пока по её панели не кликнули мышью.**
При окне доты в фокусе синтетические A/D/Space не двигали платформу вообще
(замер: сдвиг ровно 0.0 px). После клика внутрь поля — поехала. Panorama до
клика просто не отдаёт панели клавиатурный фокус.

**Захват экрана стоит 16.7 мс независимо от размера области.** Это ожидание
кадра монитора, а не копирование пикселей: снимок вдвое меньшей области стоит
столько же. Значит захват надо выносить в поток, а не оптимизировать размер.

**Один проход OCR по HUD стоит 322 мс.** В главном цикле бот на треть секунды
слеп и пропускает мяч. Тоже вынесено в поток.

**Движущийся мяч даёт ДВА пятна разницы** — «ушёл» и «пришёл». Брать первое
попавшееся значит целиться туда, откуда мяч уже улетел. Нужное выбирается по
прогнозу полёта, а при потере трека — по маске посветления (место прибытия).

**Размер имеет значение.** Пятно мяча — 1700–2300 px. Пока разрешалось от 60,
трек перехватывали искры от сбитых блоков, и платформа уезжала не туда
(в логе: цель 694, мяч упал в 390).

**С 4-го уровня кладка каменная, не оранжевая.** Состояние «идёт игра»
определялось по доле оранжевого — и живой уровень принимался за меню. Теперь
признак другой: тележка, она есть только в игре.

**Консоль бота нельзя ставить вплотную к панели.** Светлое окно рядом
склеивается с панелью в один контур при морфологическом замыкании, и панель
перестаёт находиться. Зазор 45 px, ядро замыкания уменьшено до 9x9.

## Устройство

```
run.py            единый запуск: меню, подкоманды, диагностика
main.py           бот печаталки  (цикл, ввод, статистика)
boot.py           бот арканоида  (цикл, потоки захвата и OCR, клики)

capture.py        снимок области экрана (BitBlt), поиск окна
sendkeys.py       ввод через SendInput скан-кодами, EN-раскладка, горячие клавиши
panel.py          поиск панели мини-игры и зон HUD
ocr.py            обёртка Tesseract
config.py         конфиг (config.json + дефолты)

wordfind.py       печаталка: маски цветов, строка прогресса, зелёные надписи
words.py          печаталка: словарь Dota, якорная починка OCR

arkanoid/
  vision.py       поле, тележка, мяч, блоки, состояние экрана, кнопки, HUD
  physics.py      предсказание точки падения, трекер мяча, прицел краем
  play.py         решения: куда ехать, когда пробел, выход из паузы, перезапуск
  hud.py          уровень и счёт (OCR цифр)
  templates/      шаблоны кнопок и подсказки

tools/            грабер кадров, офлайн-прогоны, бенчмарк, отчёт по словам
tests/            209 тестов (pytest)
```

## Тесты

```bash
python -m pytest tests -q
```

209 тестов: чистая математика (отскоки, предсказание, починка слов), зрение на
**настоящих кадрах игры** и сквозной прогон на синтетическом кадре. Почти
каждый баг из живых прогонов закрыт отдельным регресс-тестом — в тестах прямо
написано, что именно ломалось.

## Настройки

`config.json` рядом с проектом (создаётся при сохранении, дефолты в
`config.py` и `boot.DEFAULTS`). Полезное:

| ключ | смысл |
|---|---|
| `window_title` | часть заголовка окна игры (по умолчанию `Dota 2`) |
| `paddle_speed` | скорость тележки, px/с (замер: 200) |
| `dead_zone` | насколько близко к цели считать, что доехали |
| `aim_offset` | базовое смещение приёма мяча (0 — центром) |
| `loop_fps` | частота опроса (120 — кадры приходят каждые ~17 мс) |
| `dict_correct` | чинить ли слова печаталки по словарю |
| `hotkey_toggle` / `hotkey_quit` | коды клавиш старт/стоп и выход |
